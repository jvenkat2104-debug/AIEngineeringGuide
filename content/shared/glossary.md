# Engineering glossary

Status: Draft | Independent review pending

| Term | Plain-language meaning |
| --- | --- |
| API | An agreed interface through which programs interact |
| Architecture | The main parts of a system and their connections |
| Back end | Code that applies rules and coordinates services and data |
| Baseline | A simple reference result used to judge a more complex method |
| Database | Organised persistent storage for records |
| Data pipeline | Steps that collect, transform and move data |
| Edge | Processing at distributed network locations near users or devices in some deployments |
| Embedded system | A computer built into a device for particular tasks |
| Front end | Code for the interface and user interaction |
| Git | A tool for recording and collaborating on changes to files |
| HMAC | A shared-secret message authentication code used to check message integrity and authenticity |
| JSON | A text format for structured data |
| Middleware | Shared processing between components; its exact meaning varies |
| MLOps | Practices for operating and maintaining machine-learning systems |
| Replay attack | Reusing a captured valid message to trigger an unintended repeated action |
| SQL | A language used to work with relational data |
| System design | Decisions that make a system meet requirements and constraints |
| Trade-off | A choice that gains one benefit while accepting another cost or limitation |
| UI | The interface a person sees and interacts with |
| Verification | Checking whether a design or result meets specified requirements |

Source basis: blueprint glossary and explanations from the branch-selection guide. [Return to the roadmap](../engineering-roadmap/index.md).
