# The layers of software

**Level: Intermediate** · Start with the Year 1 roadmap if these ideas are unfamiliar.

Status: Draft | Independent review pending

| Term | Meaning | Example |
| --- | --- | --- |
| UI | What the user sees and interacts with | Buttons, labels and forms |
| Front end | Code that implements the interface and interaction | A browser or mobile application |
| API | An agreed interface between programs | A request to retrieve an order |
| Back end | Code that applies rules and coordinates data access | Checking stock before accepting an order |
| Middleware | Shared processing between other components; usage varies | Authentication checks, logging or message handling |
| Database | Organised persistent storage | Tables of products and orders |

UI includes interaction design; front-end engineering implements behaviour. Teams may use these labels differently. An API does not have to be a web API, and a database does not have to use tables.

## Follow one record

Draw how a new library loan moves from a form to validation, storage and a confirmation. Decide where to check whether the book is available. Explain why a disabled button alone cannot enforce the borrowing rule: requests may reach the server through other paths.

For a computing pathway, learn basic SQL through creating, reading and updating a small table. Check the result before and after each change. For other pathways, focus first on how measurement records are stored and retrieved in your project.
