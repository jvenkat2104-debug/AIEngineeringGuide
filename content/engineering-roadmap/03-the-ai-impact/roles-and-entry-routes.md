# Roles and realistic entry routes

**Level: Intermediate** · Start with the Year 1 roadmap if these ideas are unfamiliar.

Audience: engineering students exploring software and data pathways
Status: Draft | Independent review pending
Last updated / sources checked: 12 November 2026

Job titles overlap across employers. Compare responsibilities, qualifications and expected experience before choosing a route.

| Role | Main responsibility | Evidence a student can build |
| --- | --- | --- |
| Data analyst | Turn data into understandable answers | SQL report, chart and explanation of assumptions |
| Data/integration engineer | Deliver reliable, usable datasets | Import, transform, validate and rerun a pipeline safely |
| Data scientist | Investigate patterns and evaluate models | Baseline comparison, experimental method and limitations |
| ML engineer | Turn model behaviour into usable software | Tested inference interface and reproducible evaluation |
| AI application developer | Build an application using model capabilities | A focused workflow with evaluation, access checks and failure handling |
| MLOps/platform engineer | Enable controlled releases and reliable operation | Versioned release, monitoring and rollback demonstration |

These are teaching distinctions. A smaller team may combine several roles; a larger team may specialise further. An MLOps title can include substantial platform or cloud experience rather than entry-level model building.

## Match preparation to the work

- If you enjoy queries and explaining evidence, begin with analysis and data quality.
- If you enjoy joining systems and investigating failures, explore data integration.
- If you enjoy mathematics and experimentation, explore model development.
- If you enjoy building applications, add model integration after software foundations.
- If you enjoy repeatability, testing and incident diagnosis, explore operational responsibilities.

These prompts help exploration; they do not assign aptitude or guarantee a role.

## Routes students can investigate

Look for explicit student internships, graduate programmes, junior software/data work, testing, analytics or supervised research suited to your preparation. A possible progression through software, data or operations experience is not an automatic promotion path. Read the programme’s actual eligibility and college-placement rules.

A non-CSE degree does not prevent learning these skills, but it does not override employer degree restrictions or substitute for computing depth. Domain projects in energy, machines or infrastructure can connect your branch with data work while preserving its core foundations.

## A role-comparison worksheet

For three actual postings record: title, employer, location, source/check date, employment type, qualification, minimum experience, required skills, preferred skills and project evidence you can show. Mark each as **eligible now**, **needs verification**, or **future learning reference**. Do not label a position a fresher role just because its title includes “Associate”.
